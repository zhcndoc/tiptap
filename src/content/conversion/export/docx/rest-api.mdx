DOCX 导出 API 会将 Tiptap JSON 文档转换为 `.docx`（Microsoft Word）文件。它使用与 [编辑器扩展](/conversion/export/docx/editor-extension) 相同的转换库，并为标准内容生成等效的 DOCX 输出。

REST API 支持 [样式覆盖](/conversion/export/docx/styles)、通过 DSL 进行的 [自定义节点渲染](/conversion/export/docx/custom-nodes-dsl)、页面大小和页边距、页眉/页脚、评论线程，以及元素级覆盖（`tableOverrides`、`paragraphOverrides`、`textRunOverrides`、`tableCellOverrides`、`imageOverrides`）。它不接受基于 JavaScript 函数的选项。对于基于函数的自定义节点 API，请使用 [编辑器扩展](/conversion/export/docx/editor-extension)，它同样也可在服务器端工作。

## 导出 DOCX

`POST /v2/convert/export/docx`

`/v2/convert/export/docx` 端点会将 Tiptap 文档转换为 `DOCX` 格式。用户可以向该端点 `POST` 文档，并使用多种参数在转换过程中自定义不同文档元素的处理方式。

<Callout title="支持导出自定义" variant="info">
  `/v2/convert/export/docx` 端点接受 [样式覆盖](/conversion/export/docx/styles)、页面大小/边距、页眉/页脚、五种元素级覆盖（`tableOverrides`、
  `paragraphOverrides`、`textRunOverrides`、`tableCellOverrides`、`imageOverrides`），以及通过 JSON DSL 的 [自定义节点渲染](/conversion/export/docx/custom-nodes-dsl)。它不
  接受 JavaScript 函数选项。对于基于函数的自定义节点 API，请使用 [编辑器扩展](/conversion/export/docx/editor-extension) 或 [服务端导出
  指南](/conversion/export/docx/editor-extension#server-side-export)。
</Callout>

### 示例（cURL）

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"attrs\":{\"textAlign\":\"left\"},\"content\":[{\"type\":\"text\",\"text\":\"欢迎参加本次演示，展示我们的编辑器如何将各种格式选项导出为 DOCX，确保您的内容在 Word 中保持预期外观。\"}]}]}",
      "exportType": "blob"
    }'
```

#### Page Size Configuration

The `pageSize` object allows you to customize the dimensions of your exported DOCX document:

| Property | Type     | Description                                                                                          | Default    |
| -------- | -------- | ---------------------------------------------------------------------------------------------------- | ---------- |
| `width`  | `string` | 页面的宽度。必须是一个正数，后跟有效单位（cm、in、pt、pc、mm、px）。  | `"21.0cm"` |
| `height` | `string` | 页面的高度。必须是一个正数，后跟有效单位（cm、in、pt、pc、mm、px）。 | `"29.7cm"` |

**带自定义页面尺寸的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"自定义页面尺寸的文档\"}]}]}",
      "exportType": "blob",
      "pageSize": {"width": "21.0cm", "height": "29.7cm"}
    }'
```

#### 页眉和页脚

`headers` 和 `footers` 对象允许您自定义导出 DOCX 的一系列页眉和页脚选项。

##### 页眉配置

`headers` 对象允许您自定义导出 DOCX 文档的页眉：

| 属性 | 类型 | 描述 |
| -------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddHeaders` | `boolean` | 是否使用不同标头对于奇数页和偶数页 |
| `differentFirstPage` | `boolean` | 是否在首页上使用不同的页眉。当 `true` 时，第一页上使用 `first` 值而不是 `default`。                                                                           |
| `default` | `string \| Object` | 每页上的标准默认页眉，或激活 `evenAndOddHeaders` 选项时奇数页上的页眉。接受纯文本、字符串化 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |
| `first` | `string \| Object` | 第一页上的标题。仅当 `differentFirstPage` 设置为 `true` 时使用。接受纯文本、字符串化 Tiptap JSONContent 或 Tiptap JSONContent 对象。                                 |
| `even` | `string \| Object` | 激活 `evenAndOddHeaders` 选项时偶数页上的页眉。接受纯文本、字符串化 Tiptap JSONContent 或 Tiptap JSONContent 对象。                                          |

<Callout title="接受的槽值">
  每个标头值可以是以下三种形状之一：

- A **纯文本字符串。** 生成简单的无样式标头。
- A **字符串化 Tiptap JSONContent。** 启用丰富的格式，例如粗体、斜体和链接。使用 `JSON.stringify(yourHeaderDoc)` 生成它。
- A **Tiptap JSONContent 对象。** 相同的丰富内容，作为请求正文内的嵌套 JSON 对象发送，而不对其进行字符串化。

在 JSON 请求正文中，对象必须包含 `type` 字段，无效形状将返回 `400 Bad Request`。

</Callout>

**带自定义页眉的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"带自定义页眉的文档\"}]}]}",
      "exportType": "blob",
      "headers": {"evenAndOddHeaders": true, "default": "默认页眉", "first": "首页页眉", "even": "偶数页页眉"}
    }'
```

#### 页脚配置

`footers` 对象允许您自定义导出 DOCX 文档的页脚：

| 属性 | 类型 | 说明 |
| -------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddFooters` | `boolean` | 奇数页和偶数页是否使用不同的页脚 |
| `differentFirstPage` | `boolean` | 是否在首页上使用不同的页脚。当 `true` 时，第一页上使用 `first` 值而不是 `default`。                                                                           |
| `default` | `string \| Object` | 每页上的标准默认页脚，或激活 `evenAndOddFooters` 选项时奇数页上的页脚。接受纯文本、字符串化 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |
| `first` | `string \| Object` | 第一页的页脚。仅当 `differentFirstPage` 设置为 `true` 时使用。接受纯文本、字符串化 Tiptap JSONContent 或 Tiptap JSONContent 对象。                                 |
| `even` | `string \| Object` | 激活 `evenAndOddFooters` 选项时偶数页上的页脚。接受纯文本、字符串化 Tiptap JSONContent 或 Tiptap JSONContent 对象。                                          |

<Callout title="接受的槽值">
  每个页脚值可以是与页眉值相同的三种形状之一：纯文本字符串、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。在 JSON 请求正文中，对象必须包含 `type` 字段，无效形状将返回 `400 Bad Request`。
</Callout>

<Callout title="`{page}` / `{total}` tokens become live Word fields" variant="info">
  REST API 将页眉/页脚内的 `{page}`、`{total}` 和 `{numpages}` 同义词转换为导出的 `.docx` 中的实时 Word `PAGE` / `NUMPAGES` 字段。这适用于每种槽形状：纯文本字符串、字符串化 Tiptap JSON 或 Tiptap JSON 对象。自定义令牌名称（例如 `{p}` / `{pages}`）需要传递可选的 `placeholders` 重命名映射。请参阅下面的[自定义代币名称](#custom-token-names-placeholders)。传递 `"placeholders": false` 以将令牌作为文字文本发送。
</Callout>

#### 自定义标记名称 (`placeholders`)

当编辑器通过 [`Pages.configure({ placeholders })`](/pages/core-concepts/page-header-footer#renaming-or-disabling-placeholders) 重命名内置标记时，请将同样的重命名映射传给 REST API，以保持传输格式一致。该字段在传输层中的名称和结构与编辑器选项相同：

```json
{
  "doc": "{\"type\":\"doc\",\"content\":[]}",
  "footers": { "default": "{p} of {pages}" },
  "placeholders": { "page": "p", "total": "pages" }
}
```

当省略该映射时，服务会回退为识别 `{page}`、`{total}` 和 `{numpages}`（Word 对总页数字段的拼写，这里保留为同义词，以便直接调用 REST API 的用户能够镜像 `/import/docx` 的输出）。重命名 `total` 会移除 `{numpages}` 同义词，因此旧标记将按字面文本渲染；该重命名是严格生效的。传入 `"placeholders": false` 可为所有位置禁用替换，从而使所有 `{page}` / `{total}` 文本都以字面形式保留，不生成动态字段。

**带自定义页脚的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"带自定义页脚的文档\"}]}]}",
      "exportType": "blob",
      "footers": {"evenAndOddFooters": true, "default": "默认页脚", "first": "首页页脚", "even": "偶数页页脚"}
    }'
```

### 评论

传入一个 `comments` 对象，以便在导出的 `.docx` 中将评论线程嵌入为原生 Word 注释。每个线程都通过文档自身的评论标记锚定到其所属文本：一个 `inlineThread` 标记，其 `data-thread-id` 与线程 `id` 匹配，或者一个 `blockThread` 节点。`comments` 字段提供线程正文、作者、日期以及已解决状态。

其结构与编辑器的导出扩展一致：

| 字段                 | 类型               | 描述                                                                                                                    |
| -------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `threads`            | `Array`            | 要嵌入的评论线程。                                                                                                  |
| `threads[].id`       | `String`           | 线程 id。必须与 `doc` 中匹配的 `inlineThread` / `blockThread` 上的 `data-thread-id` 一致。                            |
| `threads[].resolvedAt` | `String \| null`   | 设置后，该线程将导出为已解决。                                                                                  |
| `threads[].comments` | `Array`            | 该线程的消息，先是根消息，然后按顺序排列回复。                                                                      |
| `comments[].id`      | `String`           | 消息 id。                                                                                                                    |
| `comments[].content` | `String \| Object` | 消息正文，纯文本或 Tiptap JSON。                                                                                 |
| `comments[].data`    | `Object`           | 可选元数据：`author`、`initials`、`dateIso`、`dateUtc`，以及往返标识（`originalWId`、`originalDurableId`）。 |

如果省略该字段，导出内容将不包含评论，因此现有请求不会受到影响。

**带有评论线程的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Reviewed text\",\"marks\":[{\"type\":\"inlineThread\",\"attrs\":{\"data-thread-id\":\"T1\"}}]}]}]}",
      "exportType": "blob",
      "comments": {
        "threads": [
          {
            "id": "T1",
            "resolvedAt": null,
            "comments": [
              {
                "id": "c1",
                "content": "请注明来源。",
                "data": { "author": "Ada Lovelace", "initials": "AL", "dateIso": "2026-01-01T00:00:00.000Z" }
              }
            ]
          }
        ]
      }
    }'
```

### 脚注和尾注

通过 `footnotes` 和 `endnotes` 导出 Word 脚注和尾注。每个都是由注释 id 键控的对象，每个值都是带有 `"type": "doc"` 的 Tiptap JSON 文档。当 `doc` 中的 `footnoteReference` 或 `endnoteReference` 节点的 `noteId` 属性在匹配对象中具有条目时，该节点将成为 Word 注释。导出时会留下没有条目的参考文献。非 Tiptap JSON 文档的值返回 `400 Bad Request`。

该形状与 [DOCX import](/conversion/import/docx/rest-api) 返回的 `footnotes` 和 `endnotes` 字段匹配。在 `multipart/form-data` 请求中，将每个字段作为 JSON 字符串发送。

**带有脚注的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Body text\"},{\"type\":\"footnoteReference\",\"attrs\":{\"noteId\":\"1\"}}]}]}",
      "footnotes": {
        "1": { "type": "doc", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "A footnote." }] }] }
      }
    }'
```

### 响应

成功时，API 以二进制形式返回 DOCX 文件下载：

- **状态**: `200 OK`
- **Content-Type**: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- **Content-Disposition**: `attachment; filename=export-{timestamp}.docx`

### 错误响应

| Status | Code                             | Description                          |
| ------ | -------------------------------- | ------------------------------------ |
| 400    | `NO_DOCUMENT_PROVIDED`           | 文档未在请求体中提供 |
| 422    | `FAILED_TO_PARSE_DOCX_FILE`      | 解析 JSON 输入失败 |
| 422    | `FAILED_TO_EXPORT_DOCX_FILE`     | 导出 DOCX 失败 |
| 422    | `FAILED_TO_CONVERT_DOCX_TO_BLOB` | 转换结果类型失败 |

## 转换字体

`POST /v2/convert/fonts/convert`

将字体转换为可嵌入 DOCX 文件的形式：`TTF` / `OTF` 上传会原样返回，而 `WOFF2` 上传会转换为 `TTF`。这是编辑器扩展的 [`embedFonts`](/conversion/export/docx/fonts#automatic-embedding) 选项在后台调用的端点；你也可以直接调用它。自 Convert Service **v2.25.0** 起可用。

<Callout>
  该端点是无状态的：不会存储任何内容。每个请求都会被转换，临时文件会立即清理。
</Callout>

### 必需请求头

```bash
Authorization: Bearer <your-jwt>
```

### 请求体

`multipart/form-data`:

| 字段         | 类型      | 描述                                               | 必填 |
| ------------ | --------- | -------------------------------------------------- | ---- |
| `file`       | `File`    | 字体二进制文件（`TTF`、`OTF` 或 `WOFF2`）。最大 25MB。 | 是   |
| `fontFamily` | `String`  | 字体族名称，仅用于日志记录。                         | 否   |

### 示例（cURL）

```bash
curl --output MyFont.ttf -X POST "https://api.tiptap.dev/v2/convert/fonts/convert" \
  -H "Authorization: Bearer <your-jwt>" \
  -F "file=@MyFont.woff2" \
  -F "fontFamily=My Font"
```

### 响应

成功时，API 会将可嵌入的字体作为二进制下载返回：

- **状态**：`200 OK`
- **Content-Type**: `font/ttf`

### 错误响应

| Status | Code                      | Description                                            |
| ------ | ------------------------- | ------------------------------------------------------ |
| 400    | None                      | 请求验证错误（例如缺少 `file` 字段）                    |
| 413    | `FONT_FILE_TOO_LARGE`     | 上传的字体超过了 25MB 限制                               |
| 422    | `UNSUPPORTED_FONT_FORMAT` | 上传内容不是可识别的 TTF、OTF 或 WOFF2 字体             |
| 422    | `FONT_CONVERSION_FAILED`  | WOFF2 → TTF 转换未产生任何输出                           |
| 500    | `FONT_CONVERSION_FAILED`  | 转换过程中发生意外错误                                   |

`@tiptap-pro/extension-export-docx` 和 `@tiptap-pro/extension-import-docx` 扩展的最大优点之一是能够定义您 Tiptap 模式中的自定义节点应如何在 DOCX 中呈现。

这使您能够在导出的 Word 文件中保留特定于应用程序的内容。

<Callout variant="hint" title="寻找 REST 兼容版本？">

## 将自定义节点导出为 .docx

<CodeDemo isPro path="/Extensions/ExportDocxCustomNode" />

调用 `editor.exportDocx()` 时，可以在 `ExportDocxOptions` 参数中传递一个自定义节点定义数组。每个定义指定节点类型和渲染函数。

<CustomNodeConversionGuide />

### 定义自定义节点渲染函数

我们将定义在导出文档中，`Hintbox` 自定义节点应如何渲染：

```ts
// 导入 ExportDocx 扩展
import {
  convertTextNode,
  Docx,
  ExportDocx,
  lineHeightToDocx,
  pixelsToHalfPoints,
  pointsToTwips,
} from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // 其他扩展 ...
    ExportDocx.configure({
      onCompleteExport: (result) => {
        setIsLoading(false)
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      exportType: 'blob',
      customNodes: [
        {
          type: 'hintbox',
          render: (node) => {
            // 这里我们定义自定义 Hintbox 节点应如何在 DOCX 中渲染。
            // 根据文档，我们应返回一个 Docx 节点，
            // 它可以是 Paragraph、Paragraph 数组、Table、TextRun、ExternalHyperlink 或 null。
            return new Docx.Paragraph({
              children: node.content.map((content) => convertTextNode(content)),
              style: 'Hintbox', // 这里我们将自定义样式应用到 Paragraph 节点。
            })
          },
        },
      ], // 自定义节点
      styleOverrides: {
        paragraphStyles: [
          // 在这里我们定义自定义 Hintbox 节点的样式。
          {
            id: 'Hintbox',
            name: 'Hintbox',
            basedOn: 'Normal',
            next: 'Normal',
            quickFormat: false,
            run: {
              font: 'Aptos Light',
              size: pixelsToHalfPoints(16),
            },
            paragraph: {
              spacing: {
                before: pointsToTwips(12),
                after: pointsToTwips(12),
                line: lineHeightToDocx(1),
              },
              border: {
                // DOCX 颜色为十六进制，不带前导 #
                top: { style: Docx.BorderStyle.SINGLE, size: 1, color: 'b8d8ff', space: 5 },
                bottom: { style: Docx.BorderStyle.SINGLE, size: 1, color: 'b8d8ff', space: 5 },
                right: { style: Docx.BorderStyle.SINGLE, size: 1, color: 'b8d8ff', space: 5 },
                left: { style: Docx.BorderStyle.SINGLE, size: 1, color: 'b8d8ff', space: 5 },
              },
              shading: {
                type: Docx.ShadingType.SOLID,
                color: 'e6f3ff',
              },
            },
          },
        ],
      }, // 样式覆盖
    }),
    // 其他扩展 ...
  ],
  // 其他编辑器设置 ...
})
```

然后，在应用程序的后续阶段，您可以将编辑器内容导出为 `DOCX` 文件：

```ts
editor.chain().exportDocx().run()
```

You can construct any supported `DOCX` elements in the `render` function using the `Docx` library classes (`Paragraph`, `TextRun`, `Table`, etc.) that are provided via the `Docx` import from the `@tiptap-pro/extension-export-docx` package.

有关 RTL 对齐方式、百分比宽度和默认样式，请参阅[原生 DOCX 选项](/conversion/export/docx/styles#native-docx-options)。

## 使图像适合页面或表格单元格

不带 `width` 和 `height` 的图像以其像素大小导出，因此大照片会超出 Word 中的右边距。渲染图像的自定义节点可以将其保留在页面内。

`render` 获取第二个参数 `context`。它的 `maxImageWidth` 是页面文本列的宽度（以像素为单位），或者节点所在表格单元格的内容宽度（单元格宽度减去其左右边距）。列表缩进不会被减去。 `context` 是 [`customNodeDsl`](/conversion/export/docx/custom-nodes-dsl) 规则内的自定义节点的 `undefined`。

将其作为 `maxWidth` 传递到 `convertImage` 或 `convertImageRun`：

```ts
import { convertImage, ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  customNodes: [
    {
      type: 'photo',
      render: (node, context) => {
        const { src, width, height } = node.attrs ?? {}

        return convertImage({
          node: { type: 'image', attrs: { src, width, height } },
          maxWidth: context?.maxImageWidth,
        })
      },
    },
  ],
})
```

`maxWidth` 仅更改既没有 `width` 也没有 `height` 的图像。较宽的图像缩小为 `maxWidth` 并保持其纵横比。具有自己尺寸的图像和 `imageOverrides.transformation` 仍然获胜。

当节点在图像周围布置内容时，使用 `convertImageRunWithSize`。它返回运行的图像及其在文档中获得的大小（`{ imageRun, width, height }`，以像素为单位），或者对于导出跳过的图像返回 `null`。此示例将标题放在与图像一样宽的表中的图像下方：

```ts
import {
  convertImageRunWithSize,
  Docx,
  ExportDocx,
  pixelsToPoints,
  pointsToTwips,
} from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  customNodes: [
    {
      type: 'figure',
      render: async (node, context) => {
        const { src, width, height } = node.attrs ?? {}
        const image = await convertImageRunWithSize({
          node: { type: 'image', attrs: { src, width, height } },
          maxWidth: context?.maxImageWidth,
        })
        if (!image) return null

        // Word measures table widths in twips.
        const tableWidth = Math.round(pointsToTwips(pixelsToPoints(image.width)))

        return new Docx.Table({
          // A fixed layout without cell margins keeps the table exactly as wide as the image.
          layout: Docx.TableLayoutType.FIXED,
          width: { size: tableWidth, type: Docx.WidthType.DXA },
          columnWidths: [tableWidth],
          margins: { top: 0, bottom: 0, left: 0, right: 0 },
          rows: [
            new Docx.TableRow({
              children: [
                new Docx.TableCell({
                  children: [
                    new Docx.Paragraph({ children: [image.imageRun] }),
                    new Docx.Paragraph({ text: node.attrs?.caption }),
                  ],
                }),
              ],
            }),
          ],
        })
      },
    },
  ],
})
```

内置 `image` 节点不受影响：它们继续以其自己的大小导出。

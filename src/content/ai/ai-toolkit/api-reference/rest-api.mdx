服务器 AI 工具包 REST API 包含用于获取可用工具和执行工具调用的端点

<Callout title="遗留端点" variant="info">
  V4 是服务器 AI 工具包端点的当前 API 版本。V3 端点已弃用；新工作请使用
  v4。v4 还将工具定义端点重命名为 `/v4/ai/toolkit/fetch-tools`；
  `/v3/ai/toolkit/tools` 等旧名称属于 v3 API。有关遗留端点，请参阅 [v3 REST API
  参考](/ai/ai-toolkit/api-reference/rest-api-v3)。
</Callout>

## 基础 URL

Tiptap Cloud 的基础 URL 为：

```sh
BASE_URL=https://api.tiptap.dev
```

在本地部署中，基础 URL 可能会有所不同。

在下面的示例中，请求写作 `BASE_URL/v4/ai/toolkit/...`。

## 身份验证

所有请求都必须包含以下身份验证头：

- `Authorization: Bearer JWT`，其中 `JWT` 是一个 Tiptap 访问控制 JWT。

请使用以下设置在服务器端签名令牌：

- 受众：`AI`
- 权限：`AI:Toolkit`

要自动获取并保存 Tiptap Cloud 文档，请将 `Documents` 添加到受众，并添加 `Documents:Write` 权限。`Documents:Write` 包含读取和评论权限。

请参阅 [身份验证](/authentication) 了解如何创建密钥对并签名令牌，以及 [授权指南](/ai/ai-toolkit/install#set-up-authorization) 了解完整设置。

```ts
import { SignJWT, importPKCS8 } from 'jose'

const privateKey = await importPKCS8(process.env.TIPTAP_PRIVATE_KEY, 'ES256')

const JWT_TOKEN = await new SignJWT({
  permissions: [
    { action: 'AI:Toolkit', resource: '*' },
    { action: 'Documents:Write', resource: 'your-document-id' },
  ],
})
  .setProtectedHeader({ alg: 'ES256' })
  .setIssuer(process.env.TIPTAP_ENVIRONMENT_ID)
  .setAudience(['AI', 'Documents'])
  .setExpirationTime('30m')
  .sign(privateKey)
```

之前的 App ID + secret 身份验证流程记录在 [旧版身份验证](/authentication/legacy) 中。

## 可选字段

可选字段可以省略、`null` 或 `undefined`。

## 端点

### 获取工具定义

```txt
POST /v4/ai/toolkit/fetch-tools
```

返回你传递给 AI 提供商的提示词和工具定义。

请求体：

- `editorContext` (`object`，必需)：由 `getEditorContext` 返回的编辑器上下文。
- `hiddenAttributes` (`string[]`，可选，默认：`[]`)：从 schema awareness 提示词中排除的节点属性，包括它们的默认值。执行工具或流式传输受支持的工具时也要使用相同列表。`stream-tool` 不允许在 `tiptapEdit` 中使用非空的 `hiddenAttributes`；此类编辑请使用 `execute-tool`。参见[隐藏属性](#hidden-attributes)。
- `tools` (`Record<string, boolean | ToolConfig>`，可选，默认：`{}`)：启用、禁用或配置工具。工具默认处于禁用状态。
- `format` (`'json' | 'shorthand' | 'shorthandV2'`，可选，默认：`'json'`)：工具定义和模型输出所使用的文档格式。参见 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。

`tools` 可以包含以下键：

- `tiptapRead`（`boolean`，可选）
- `tiptapEdit`（`boolean | { meta?: string }`，可选）：若要让 AI 在每个编辑操作中包含额外的元数据字段（例如简短说明），请设置 `meta`。
- `tiptapQuery`（`boolean | { meta?: string }`，可选）：若要让 AI 在每个文档变更操作中包含额外的元数据字段，请设置 `meta`。参见 [`tiptapQuery`](/ai/ai-toolkit/api-reference/tiptap-query)。
- `getThreads`（`boolean`，可选）
- `editThreads`（`boolean`，可选）
- `readDocument`（`boolean`，可选）
- `replaceDocument`（`boolean`，可选）
- `createDocument`（`boolean`，可选）：`replaceDocument` 的别名。
- `readSelection`（`boolean`，可选）
- `proofread`（`boolean | { meta?: string }`，可选）：若要让 AI 在每项校对编辑中包含额外的元数据字段（例如简短说明），请设置 `meta`。
- `readBoard`、`createShapes`、`arrangeShapes`、`distributeShapes`、`createDiagram`、`updateShapes`、`deleteShapes`、`connectShapes` 和 `createDocFrame`（`boolean`，可选）：用于白板的[画板工具](#board-tools)。

响应：

- `systemPrompt`（`string`）：将其添加到 AI 请求的系统提示词中。它会说明 Tiptap 文档的工作方式、编辑器支持的元素以及应使用的文档格式。
- `tools`（`array`）：AI 或开发者可以调用的工具定义。数组中的每一项包含：
  - `name`（`string`）：工具名称。
  - `description`（`string`）：工具描述。
  - `inputSchema`（`object`）：AI 生成的工具输入所用的 JSON schema。

示例：

```curl
curl --location 'BASE_URL/v4/ai/toolkit/fetch-tools' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT' \
  --data '{
    "editorContext": { /* 编辑器上下文数据 */ },
    "tools": {
      "tiptapRead": true,
      "tiptapEdit": {
        "meta": "简要解释此次编辑。"
      }
    },
    "format": "shorthandV2"
  }'
```

#### 错误响应

HTTP 错误会返回：

- `error`（`object`）：包含以下属性的对象：
  - `message`（`string`）：便于阅读的错误消息。
  - `status`（`number`）：HTTP 状态码。
  - `code`（`string`）：稳定的错误代码。
  - `data`（`object`，可选）：经过清理的结构化上下文。

此端点可能返回：

- `401`，错误码为 `access_control_auth_required` 或 `missing_token`：请求未包含 Tiptap Access Control JWT。
- `401`，错误码为 `token_expired` 或 `signature_invalid` 等 Access Control 错误码：JWT 未通过 Access Control 验证。
- `403`，错误码为 `feature_not_available`：此环境未启用 Server AI Toolkit。
- `403`，错误码为 `insufficient_permissions`：JWT 未授予 `AI:Toolkit` 权限。
- `403`，错误码为 `origin_not_allowed`：此环境不允许该请求的 `Origin`。
- `422`，错误码为 `validation_failed`：请求体与端点 schema 不匹配。响应中的 `error.issues` 列出了验证问题。
- `422`，错误码为 `tool_config_validation_failed`：请求体中的工具配置无效。响应中的 `error.data.issues` 列出了验证问题。
- `429`，错误码为 `rate_limited`：Access Control 对身份验证请求进行了速率限制。
- `429`：服务器端速率限制器阻止了请求。此响应采用不同的顶层结构：
  - `error`（`string`）：速率限制错误消息。
  - `retryAfter`（`number`，可选）：重试前需要等待的秒数。
  - `limit`（`number`，可选）：当前时间窗口内允许的请求数。
  - `window`（`number`，可选）：速率限制窗口的秒数。
- `500`，错误码为 `internal_server_error`：发生了意外的服务器错误。
- `500`，错误码为 `missing_cloud_api_token`：云服务缺少内部身份验证配置。
- `503`，错误码为 `service_unavailable`：Access Control 暂时不可用。

### 执行工具

```txt
POST /v4/ai/toolkit/execute-tool
```

执行一个工具。在 AI 模型生成工具调用后使用此端点。

请求体：

- `editorContext` (`object`，必需)：`getEditorContext` 返回的编辑器上下文。
- `document` (`object`，必需)：要对其执行工具的文档。API 需要从 Tiptap Cloud 文档读取并写入时，使用
  `{ "type": "cloud", "id": "your-document-id" }`。当你想在请求体中提供
  Tiptap JSON 文档时，使用 `{ "type": "inline", "content": { /* Tiptap JSON 文档 */ } }`。
- `user` (`string`，可选)：版本历史中编辑的作者。它还会设置 AI 生成的评论、线程和修订记录建议所关联的用户；
  如需设置修订记录建议的作者，请使用 `reviewOptions.trackedChangesOptions.userId`。
- `field` (`string`，可选，默认：`"default"`)：要在云文档中定位的协作字段。文档存储多个可编辑字段时使用此项，例如标题和正文。
- `tool` (`object`，必需)：要执行的工具调用。
  - `name` (`string`，必需)：工具名称，例如 `"tiptapRead"`。
  - `input` (`object`，必需)：AI 生成的工具输入。这是一个与该工具的 schema 和工具定义相匹配的对象。每个工具的 schema 和工具定义可从
    `/v4/ai/toolkit/fetch-tools` 端点获取。
  - `config` (`unknown`，可选)：由开发者提供的工具特定配置。
- `format` (`'json' | 'shorthand' | 'shorthandV2'`，可选，默认：`'json'`)：工具输入和输出的文档格式。参见 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。
- `reviewOptions` ([`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认：`{ mode: 'disabled' }`)：控制编辑是直接应用还是作为可审阅更改应用。

响应：

- `tool` (`object`)：已执行的工具及其输出。
  - `name` (`string`)：工具名称。
  - `output` (`object`)：提供给 AI 的工具输出。
- `docChanged` (`boolean`)：文档是否发生了变化。
- `before` (`JSONContent`)：工具执行前的 Tiptap JSON 文档。
- `document` (`JSONContent | null`)：工具执行后的 Tiptap JSON 文档；如果文档未更改则为 `null`。变化可能包括文档内容以及节点 `_hash` 属性的修改；这些属性用作唯一标识符，使 AI 能够选择文档节点。

示例：

```curl
curl --location 'BASE_URL/v4/ai/toolkit/execute-tool' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT' \
  --data '{
    "editorContext": { /* 编辑器上下文数据 */ },
    "document": {
      "type": "cloud",
      "id": "your-document-id"
    },
    "user": "ai-assistant",
    "tool": {
      "name": "tiptapRead",
      "input": {
        "from": 0
      }
    },
    "format": "shorthandV2"
  }'
```

#### 错误响应

HTTP 错误会返回：

- `error`（`object`）：包含以下属性的对象：
  - `message`（`string`）：便于阅读的错误消息。
  - `status`（`number`）：HTTP 状态码。
  - `code`（`string`）：稳定的错误代码。
  - `data`（`object`，可选）：经过清理的结构化上下文。文档和线程的上游请求失败时，可能包含 `operation`、`upstreamStatus`、`upstreamUrl` 和 `upstreamMethod` 等字段。

此端点可能返回：

- `400`，错误码为 `missing_document_credentials`：请求使用了云文档，但 JWT 不包含文档服务器凭据。
- `400`，错误码为 `missing_document_options`：`getThreads` 或 `editThreads` 被用于内联文档。这些工具需要云文档。
- `400`，线程存储错误码为 `thread_not_found` 或 `comment_not_found` 等：线程或评论操作引用了不存在的数据。
- `401`，错误码为 `access_control_auth_required` 或 `missing_token`：请求未包含 Tiptap Access Control JWT。
- `401`，错误码为 `token_expired` 或 `signature_invalid` 等 Access Control 错误码：Access Control 拒绝了该 JWT。
- `403`，错误码为 `feature_not_available`：此环境未启用 Server AI Toolkit。
- `403`，错误码为 `insufficient_permissions`：JWT 未授予 `AI:Toolkit` 权限，或未授予对所请求云文档的访问权限。
- `403`，错误码为 `origin_not_allowed`：此环境不允许该请求的 `Origin`。
- `403`，错误码为 `unsupported_tool_format`：所选工具不支持请求的 `format`。
- `403`，错误码为 `tracked_changes_unsupported_schema`：`reviewOptions.mode` 为 `trackedChanges`，但编辑器 schema 不支持修订记录。
- `403`，错误码为 `thread_schema_not_supported`：编辑器 schema 不支持评论或线程。
- `403` 和 `board_schema_not_supported`：[白板工具](#board-tools) 获得的文档或编辑器模式不是可以使用的白板。
- `409`，错误码为 `concurrent_edit_conflict`：工具执行期间云文档发生了变化。请使用最新文档状态重试请求。
- `422`，错误码为 `validation_failed`：请求体与端点 schema 不匹配。响应中的 `error.issues` 列出了验证问题。
- `422`，错误码为 `tool_config_validation_failed`：`tool.config` 无效，例如调用 `readSelection` 时未提供 `user`。响应中的 `error.data.issues` 列出了验证问题。
- `429`，错误码为 `rate_limited`：Access Control 对身份验证请求进行了速率限制。
- `429`：服务器端速率限制器阻止了请求。此响应采用不同的顶层结构：
  - `error`（`string`）：速率限制错误消息。
  - `retryAfter`（`number`，可选）：重试前需要等待的秒数。
  - `limit`（`number`，可选）：当前时间窗口内允许的请求数。
  - `window`（`number`，可选）：速率限制窗口的秒数。
- `500`，错误码为 `document_save_failed`：服务器读取云文档后无法保存，或在文档加载前调用了保存流程。
- `500`，错误码为 `diff_worker_failed` 或 `diff_worker_invalid_result`：准备可审阅的更改时，内部 diff worker 执行失败。
- `500`，错误码为 `internal_server_error` 或 `unknown_error`：发生了意外的服务器错误。
- `500`，错误码为 `missing_cloud_api_token`：云服务缺少内部身份验证配置。
- `502`，错误码为 `document_load_failed` 或 `document_save_failed`：从上游加载或保存云文档失败。请检查 `error.data.upstreamStatus` 中的上游 HTTP 状态码。
- `502`，线程或评论错误码为 `thread_list_failed`、`thread_create_failed`、
  `thread_update_failed`、`thread_delete_failed`、`thread_resolve_failed`、
  `thread_unresolve_failed`、`comment_create_failed`、`comment_update_failed` 或
  `comment_delete_failed`：线程或评论 API 操作在上游失败。
- `503`，错误码为 `diff_worker_queue_timeout`：diff worker 队列已饱和或超时。
- `503`，错误码为 `service_unavailable`：Access Control 暂时不可用。

### 流式执行工具

```txt
POST /v4/ai/toolkit/stream-tool
```

以流式方式执行工具。`tiptapEdit` 可以逐步应用编辑，以实现打字效果。其他工具会在接收到完整输入后
运行，并返回一个最终事件，就像 `execute-tool` 一样。

请求分批发送。第一部分包含：

- `editorContext` (`object`，必需)：由 `getEditorContext` 返回的编辑器上下文。
- `document` (`object`，必需)：要将编辑流式写入的云文档：
  `{ "type": "cloud", "id": "your-document-id" }`。内联文档不支持
  流式传输。
- `user` (`string`，可选)：版本历史、评论和线程中编辑的作者（例如与 `editThreads` 一起使用）。它不会设置修订记录建议的作者；如需设置修订记录作者，请使用 `reviewOptions.trackedChangesOptions.userId`。
- `field` (`string`，可选，默认：`"default"`)：要在云文档中定位的协作字段。流式传输仅支持 `default` 字段；使用任何其他值都会被拒绝。
- `tool` (`object`，必需)：要执行的工具调用，不包含 `tool.input`。
  - `name` (`string`，必需)：工具名称，例如 `"tiptapEdit"`。
  - `config` (`unknown`，可选)：开发者提供的工具特定配置。
- `format` (`'json' | 'shorthand' | 'shorthandV2'`，可选，默认：`'json'`)：工具输入和输出的文档格式。参见 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。
- `reviewOptions` ([`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认：`{ mode: 'disabled' }`)：控制编辑是直接应用还是作为可审阅更改。
- `delayMs` (`number`，可选，默认：`5`)：`tiptapEdit` 增量输出中每个字符的延迟，单位为毫秒。必须介于
  `0` 和 `1000` 之间。使用 `0` 可尽可能快地应用编辑。

然后发送：

- 后续部分：`tool.input` 的值，在 AI 生成时以流式方式发送。

响应：

- `tiptapEdit`：在编辑被应用时返回增量事件，随后返回一个包含
  更新后 `document` 的最终事件。
- 其他工具：返回一个最终事件，结果结构与 `execute-tool` 相同。

#### 错误响应

在流式传输开始之前，HTTP 错误使用与 `execute-tool` 相同的 JSON 结构：

- `error`（`object`）：包含以下属性的对象：
  - `message`（`string`）：便于阅读的错误消息。
  - `status`（`number`）：HTTP 状态码。
  - `code`（`string`）：稳定的错误代码。
  - `data`（`object`，可选）：经过清理的结构化上下文。

在流式传输开始之后，错误会以 NDJSON 事件形式发送：

- `version`（`number`）：流协议版本。
- `type`（`'error'`）：事件类型。
- `code`（`string`）：稳定的错误代码。
- `status`（`number`）：类似 HTTP 状态码的数值。
- `message`（`string`）：便于阅读的错误消息。

此端点可能返回或发出：

- `400`，错误码为 `invalid_request`：请求没有正文。
- `400`，错误码为 `missing_document_credentials`：JWT 不包含文档服务器凭据。
- `400`，错误码为 `invalid_stream_message`：流消息不是有效的 JSON，未通过 schema 验证，
  使用了不支持的协议版本，或者流在 NDJSON 行未终止时结束。
- `400`，错误码为 `duplicate_start`：发送了多个 `start` 消息。
- `400`，错误码为 `delta_before_start`：`delta` 消息在 `start` 之前到达。
- `400`，错误码为 `end_before_start`：`end` 消息在 `start` 之前到达。
- `400`，错误码为 `incomplete_stream`：请求在收到 `end` 消息之前结束。
- `400`，线程存储错误码为 `thread_not_found` 或 `comment_not_found` 等：缓冲的
  线程或评论操作引用了不存在的数据。
- `401`，错误码为 `access_control_auth_required` 或 `missing_token`：请求未包含
  Tiptap Access Control JWT。
- `401`，错误码为 `token_expired` 或 `signature_invalid` 等 Access Control 错误码：JWT 被
  Access Control 拒绝。
- `403`，错误码为 `feature_not_available`：当前环境未启用 Server AI Toolkit。
- `403`，错误码为 `insufficient_permissions`：JWT 未授予 `AI:Toolkit` 权限。
- `403`，错误码为 `origin_not_allowed`：当前环境不允许请求的 `Origin`。
- `403`，错误码为 `tracked_changes_unsupported_schema`：`reviewOptions.mode` 为 `trackedChanges`，但编辑器 schema 不支持修订记录。
- `403`，错误码为 `thread_schema_not_supported`：编辑器 schema 不支持评论或线程。
- `413`，错误码为 `ndjson_line_too_long`：单条 NDJSON 消息超过允许的最大长度。
- `429`，错误码为 `stream_rate_limit_exceeded`：同一客户端打开的并发流数量过多。
- `429`，错误码为 `rate_limited`：Access Control 对身份验证请求进行了速率限制。
- `429`：服务器端限流器在流式传输开始前阻止了请求。此响应采用不同的顶层结构：
  - `error`（`string`）：限流错误消息。
  - `retryAfter`（`number`，可选）：重试前需要等待的秒数。
  - `limit`（`number`，可选）：当前窗口内允许的请求数。
  - `window`（`number`，可选）：限流窗口的秒数。
- `500`，错误码为 `diff_worker_failed`、`diff_worker_invalid_result`、`stream_internal_error` 或 `unknown_error`：流处理期间发生了意外的服务器错误。
- `500`，错误码为 `missing_cloud_api_token`：云服务缺少内部身份验证配置。
- `502`，错误码为 `document_load_failed`、`document_save_failed`、`thread_list_failed` 或 `comment_create_failed` 等文档、线程或评论上游错误：云文档或评论 API 操作在上游失败。
- `503`，错误码为 `diff_worker_queue_timeout`：diff worker 队列已饱和或超时。
- `503`，错误码为 `service_unavailable`：Access Control 暂时不可用。
- `504`，错误码为 `stream_request_timeout`：流处理超过了服务器请求超时时间。

## 可用工具

这些工具可供 AI 代理使用。代理决定调用哪个工具。

所有工具默认都处于禁用状态。我们建议先使用 `tiptapRead` 和 `tiptapEdit`，然后
根据需要启用其他工具。

你也可以直接从应用程序代码中调用这些工具，以构建自定义工作流。

### 读取时的属性默认值

`tiptapRead`、`readDocument`、`readSelection`、`getThreads` 和 `tiptapQuery` 在读取时会自动省略与 schema 默认值相同的节点和标记属性。此规则适用于 JSON 和两种 Shorthand 格式，包括通过 `execute-tool` 执行的读取，以及 `stream-tool` 支持的读取操作。无需额外配置。

例如，当 schema 默认级别为 `1` 时，标题节点的 `level: 1` 会被省略，而 `level: 2` 会保留。此规则同样适用于 `null`、布尔值、字符串以及结构相同的数组和对象。没有 schema 默认值的属性会保留在输出中，除非显式将其隐藏。

因等于 schema 默认值而省略的属性仍保留该默认值。`hiddenAttributes` 中的属性无论实际值为何都会被省略；省略它们并不表示它们使用默认值。`fetch-tools` 返回的 `systemPrompt` 会包含这些默认值，使 AI 能正确理解读取结果并写回内容，而不会丢失属性值。这样可以缩短读取结果，同时不改变文档。

### 隐藏属性

在 `execute-tool` 和 `stream-tool` 请求中使用 `hiddenAttributes` 字段（`string[]`），可阻止 AI 读取节点属性，例如仅供导出使用的布局设置。`tiptapRead`、`tiptapEdit`、`tiptapQuery`、`replaceDocument`、`createDocument`、`readSelection`、`getThreads` 和 `readDocument` 都支持此字段：通过这些工具，AI 无法读取或修改指定属性，文档中的属性值会保留。其他工具会忽略此字段，因此[画板工具](#board-tools)仍会读取和写入形状的全部属性，例如文档框架的 `docId`。每次读取或编辑文档时都要传入相同的属性列表。

- 读取结果不会包含这些属性。
- 编辑操作会忽略 AI 为这些属性写入的值。文本未变化的节点会保留原值，即使节点被移动也是如此。发生变化的节点会保留被其替换的同类型节点的属性值；即使 AI 重写整个表格或列表并增删行，也会保留这些值。段落被 AI 拆分为多个段落时，原属性值会传递给拆分后的每个段落。
- 新内容（例如新增的表格行）以及类型发生变化的节点（例如改成标题的段落）会使用 schema 默认值。AI 通过单独的插入和删除操作移动节点时，该节点也会被视为新内容。
- 一次编辑新增节点并完全重写相邻节点的文本时，属性值可能会转移到新增节点上。
- AI 无法执行依赖这些属性的请求，例如将行高调小。
- 只能隐藏节点属性。`_hash` 和修订记录属性不能隐藏。属性列表无效时，`execute-tool` 会返回 `422` 和 `validation_failed`，`stream-tool` 会返回 `400` 和 `invalid_stream_message`。
- `stream-tool` 会以 `invalid_stream_message` 拒绝 `tiptapEdit` 的此选项，因为流式编辑无法保留这些属性值。

## 白板工具

<Callout title="Alpha 功能" variant="hint">
  白板工具目前处于 Alpha 阶段。
</Callout>

这些工具会读取和修改[白板](/editor/whiteboard/getting-started/overview)。请在白板文档上使用白板编辑器的上下文执行它们。设置方法请参阅[与白板搭配使用](/ai/ai-toolkit/agents/whiteboard)。

白板工具处理的是形状数据，而不是文档内容，因此不受 `format` 影响。它们无法通过 `stream-tool` 使用。

无法执行的白板工具不会进行任何更改。如果模型能够修正调用，例如调整与白板不匹配的 schema 或 ID，工具会返回 HTTP `200`，并在工具输出中设置 `success: false` 和 `error`。

当请求本身无法工作时，`execute-tool` 会像其他工具一样失败：

- `403`，错误码为 `board_schema_not_supported`：文档或编辑器上下文不是该工具支持的白板，例如缺少 `createDocFrame` 文档框架的白板。
- `403`，错误码为 `tracked_changes_unsupported_schema`：修改白板的工具使用了 `reviewOptions.mode: 'trackedChanges'`，但编辑器上下文不支持修订记录。`readBoard` 不检查此项。

### 白板工具配置

`readBoard`、`createShapes`、`createDiagram` 和 `createDocFrame` 接受以下工具配置（`tool.config`）：

- `selectedIds`（`string[]`，可选）：用户所选形状的 ID，按选择顺序排列。
- `viewport`（`{ x: number, y: number, width: number, height: number }`，可选）：用户当前看到的白板区域，以白板单位表示。`width` 和 `height` 必须大于 `0`。

每个缺失、值为 `null` 或无效的字段都会单独回退：不指定选区或视口。

### 白板内容的放置

`createShapes`、`createDiagram` 和 `createDocFrame` 在输入（`tool.input`）中接受以下字段，以便 AI 指定新内容的位置：

- `near`（`string[]`，可选）：最多 100 个形状的 ID，新内容会放在这些形状附近，例如摘要所涉及图表的 ID。默认使用所选形状。
- `side`（`'right' | 'below' | 'left' | 'above'`，可选）：新内容相对这些形状的方位。通常默认放在右侧或下方，具体取决于哪个空位更近。

新形状会放在白板上 `near` 指定的形状旁边，或放在所选形状旁边。如果没有合适的形状，则放在视口中央；视口不可用时，放在白板上所有形状的右侧；如果白板为空，则放在原点。若目标位置被其他形状占据，新形状会移到最近的空位。

### 白板更改建议

使用 `reviewOptions.mode: 'trackedChanges'` 时，白板工具会将更改记录为[修订记录](/tracked-changes/getting-started/overview)：

- 一次调用中添加或删除的形状共用一个建议，因此 `acceptSuggestion` 或 `rejectSuggestion` 会一并审核这些更改。
- 每个被修改的形状和每段新文本都有自己的建议。同一用户稍后作出的待审阅形状修改会并入该建议。
- 这些工具会跳过等待其他用户审核的形状，以及等待审核删除的形状；也不会删除仍有待审阅修改的形状。跳过原因会列在 `skipped` 或 `skippedArrows` 中。

`suggestionIds`（`string[]`）列出本次调用新建或继续更新的建议。继续更新建议时，先前的更改也会保留。若本次修改的是先前建议新增的形状，该修改会并入原建议，因此不会重复列出。审核这些 ID 时，其他建议不会变化。未启用审核时，`suggestionIds` 为空，工具会保留所有待审核形状。

### `readBoard`

读取棋盘的形状、它们之间的箭头以及选择。它不会更改文档。

工具输入 (`tool.input`)：

该工具不接受任何输入。传递一个空对象（`{}`）。

工具配置 (`tool.config`):

[板工具配置](#board-tool-config)。

工具输出 (`tool.output`)：

成功响应：

- `success` (`true`)：表示已读取电路板。
  - `shapeCount` (`number`)：白板上的形状数量，包括箭头。
  - `selectedIds` (`string[]`)：白板上所选形状的 ID。
- `shapes` (`array`)：形状，首先选择形状。
  - `id` (`string`)：唯一形状标识符。
  - `type` (`string`)：节点类型，例如 `stickyNote`、`geo`、`freeText`、`freehand` 或 `docFrame`。
  - `kind?` (`string`)：一种几何形状，如 `rectangle` 或 `diamond`。
  - `x`、`y`、`width`、`height` (`number`)：盒子形状，以整板为单位。 `y` 向下增长。
  - `color?` (`string`)：颜色名称，如 `yellow`。
  - `text?` (`string`)：形状文本，每个段落或列表项一行。列表项以 `- `、`1. `、`[ ] ` 或 `[x] ` 开头。未选择的形状的文本将在 280 个字符后被剪切。
  - `docId?` (`string`)：文档框架显示的文档的 ID。每个文档框架都有它。对于没有 `docId` 属性的框架，它是形状 id，框架显示其文档。
  - `selected?` (`true`)：用户选择形状。
  - `suggestion?` (`'add' | 'delete' | 'change'`)：等待审核的建议，并添加或删除形状，或者更改其属性或文本。
- `arrows` (`array`)：板上的箭头。
  - `id` (`string`)：唯一箭头标识符。
  - `fromId` (`string | null`)：箭头开始处的形状的 ID，或 `null` 表示自由端。
  - `toId` (`string | null`)：箭头指向的形状的 ID，或 `null` 表示自由端。
- `omittedShapeCount` (`number`)：输出遗漏的形状和箭头的数量。最多列出 300 个。
- `viewport` (`object | null`)：工具配置的 `viewport`。

### `arrangeShapes`

工具配置 (`tool.config`)：

`null`

工具输出 (`tool.output`)：

- `titleIds` (`string[]`)：新标题的 ID。
- `skipped` (`array`)：保持原样的形状，每个形状都有 `id` 和 `reason`，例如不是板上形状的 id、箭头、早期组命名的 id 或等待其他用户审阅的形状。

### `distributeShapes`

将形状按其沿排列方向的顺序排成一行或一列，并在形状之间留出相等间距。形状沿中线对齐。排列时会保留形状两端的外边缘；如果形状间距不足 48 个白板单位，则将间距调整为 48。当排列结果会遮挡其他形状时，会将整组移动到最近的空位；形状所属的框架不计作遮挡。该操作只移动形状，因此连接它们的箭头也会随之移动，移动框架中的形状也会一同移动。

工具输入（`tool.input`）：

- `ids`（`string[]`，必需）：要排列的 2 至 300 个形状 ID。
- `direction`（`'horizontal' | 'vertical'`，可选）：`horizontal` 表示从左向右排列成一行，`vertical` 表示从上向下排列成一列。默认值：`'horizontal'`。

工具配置（`tool.config`）：

`null`

工具输出（`tool.output`）：

成功响应：

- `success`（`true`）：表示形状已完成排列。
- `movedIds`（`string[]`）：已移动的形状 ID，包括随框架一同移动的形状。不包含原本就在目标位置的形状。
- `skipped`（`array`）：未移动的形状及其 `id` 和 `reason`，例如 ID 不对应白板上的形状、对应的是箭头、ID 已由前面的条目处理，或形状正在等待其他用户审核。
- `suggestionIds`（`string[]`）：参见[白板更改建议](#board-suggestions)。

错误响应：

- `success`（`false`）：表示无法排列至少两个形状。错误消息会列出原因。
- `error`（`string`）：错误消息。

### `createDiagram`

用文本绘制形状，通过箭头连接，并将它们布置为图表。箭头连接形状，因此当用户移动形状时它们会跟随。

刀具输入 (`tool.input`)：

- `title`（`string`，可选）：图表上方的标题，最多 80 个字符。
  - `direction`（`'down' | 'right'`，可选）：箭头的主要指向。默认值：`'down'`。
  - `nodes`（`array`，必需）：1 到 40 个形状。
  - `key`（`string`，必填）：AI 自己的形状名称，最多 40 个字符，并且在图中是唯一的。箭头指的是它。
  - `text`（`string`，必需）：形状中的文本，最多 60 个字符。
  - `shape`（`'rectangle' | 'ellipse' | 'diamond'`，可选）：形状类型。默认值为长方形，即 `'rectangle'`。
  - `color`（`string`，可选）：`createShapes` 的颜色之一。默认值：`'black'`
- `arrows`（`array`，可选）：最多 60 个箭头。
  - `from`（`string`，必需）：箭头开始处的形状的关键点。
  - `to`（`string`，必需）：箭头指向的形状的键。
  - `label`（`string`，可选）：箭头旁边的标签，最多 24 个字符。
- `near` 和 `side`（可选）：图表所在的位置。请参阅[董事会布局](#board-placement)。

工具配置 (`tool.config`):

[板工具配置](#board-tool-config)。

工具输出 (`tool.output`)：

成功响应：

- `success` (`true`)：表示已绘制图表。
- `createdIds` (`string[]`)：所有新形状的 ID：标题、形状、箭头及其标签。
- `nodeIds` (`Record<string, string>`)：每个新形状的 ID（按其键）。
- `skippedArrows` (`array`)：省略的箭头，每个箭头都有 `from`、`to` 和 `reason`。带有未知键的箭头（从形状到自身）或较早出现的箭头将被忽略。
- `suggestionIds`（`string[]`）：参见[白板更改建议](#board-suggestions)。

错误响应：

- `success` (`false`)：表示未绘制图表。
- `error` (`string`)：错误消息。

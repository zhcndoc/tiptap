服务器 AI 工具包 REST API 包含用于获取可用工具和执行工具调用的端点

<Callout title="遗留端点" variant="info">
  V4 是服务器 AI 工具包端点的当前 API 版本。V3 端点已弃用；新工作请使用
  v4。v4 还将工具定义端点重命名为 `/v4/ai/toolkit/fetch-tools`；
  `/v3/ai/toolkit/tools` 等旧名称属于 v3 API。有关遗留端点，请参阅 [v3 REST API
  参考](/ai/ai-toolkit/api-reference/rest-api-v3)。
</Callout>

## 如何提供文档

Tiptap Cloud 的基础 URL 为：

```sh
BASE_URL=https://api.tiptap.dev
```

在本地部署中，基础 URL 可能会有所不同。

在下面的示例中，请求写作 `BASE_URL/v4/ai/toolkit/...`。

## 身份验证

所有请求都必须包含以下身份验证头：

- `Authorization: Bearer JWT`，其中 `JWT` 是一个 Tiptap 访问控制 JWT。

请使用以下设置在服务器端签名令牌：

- Audience: `AI`
- Permissions: `AI:Toolkit`

要自动获取并保存 Tiptap Cloud 文档，请添加 `Documents` audience 和 `Documents:Write` permission。`Documents:Write` 包含读和评论访问权限。

请参阅 [身份验证](/authentication) 了解如何创建密钥对并签名令牌，以及 [授权指南](/ai/ai-toolkit/install#set-up-authorization) 了解完整设置。

```ts
import { SignJWT, importPKCS8 } from 'jose'

const privateKey = await importPKCS8(process.env.TIPTAP_PRIVATE_KEY, 'ES256')

const JWT_TOKEN = await new SignJWT({
  permissions: [
    { action: 'AI:Toolkit', resource: '*' },
    { action: 'Documents:Write', resource: 'your-document-id' },
  ],
})
  .setProtectedHeader({ alg: 'ES256' })
  .setIssuer(process.env.TIPTAP_ENVIRONMENT_ID)
  .setAudience(['AI', 'Documents'])
  .setExpirationTime('30m')
  .sign(privateKey)
```

之前的 App ID + secret 身份验证流程记录在 [旧版身份验证](/authentication/legacy) 中。

## 可选字段

可选字段可以省略、`null` 或 `undefined`。

## 终端点。

### 获取工具定义

```txt
POST /v4/ai/toolkit/fetch-tools
```

返回你传递给 AI 提供商的提示词和工具定义。

请求体：

- `editorContext` (`object`，必需)：由 `getEditorContext` 返回的编辑器上下文。
- `tools` (`Record<string, boolean | ToolConfig>`，可选，默认：`{}`)：启用、禁用或
  配置工具。工具默认处于禁用状态。
- `format` (`'json' | 'shorthand' | 'shorthandV2'`，可选，默认：`'json'`)：工具
  定义和模型输出所使用的文档格式。参见 [Tiptap
  Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。

`tools` 可以包含以下键：

- `tiptapRead` (`boolean`, optional)
- `tiptapEdit` (`boolean | { meta?: string }`, optional): 当你希望 AI 在每次编辑操作中
  包含一个额外的元数据字段时设置 `meta`，例如简短说明。
- `tiptapQuery` (`boolean | { meta?: string }`, optional): Set `meta` when you want the AI to
  在你希望 AI 为每个会更改文档的操作添加额外元数据字段时设置 `meta`。参见
  [`tiptapQuery`](/ai/ai-toolkit/api-reference/tiptap-query).
- `getThreads` (`boolean`, optional)
- `editThreads` (`boolean`, optional)
- `readDocument` (`boolean`, optional)
- `replaceDocument` (`boolean`, optional)
- `createDocument` (`boolean`, optional): Alias for `replaceDocument`.
- `readSelection` (`boolean`, optional)
- `proofread` (`boolean | { meta?: string }`, optional): Set `meta` when you want the AI to
  include an extra metadata field on every proofreading edit, such as a short explanation.
- `readBoard`， `createShapes`、`arrangeShapes`、`createDiagram`、`updateShapes`、`deleteShapes`、`connectShapes` 和 `createDocFrame`（`boolean`，可选）：[板工具](#board-tools)，用于白板。

响应：

- `systemPrompt` (`string`): 将其添加到你 AI 请求的 system prompt 中。它会教会 AI
  Tiptap 文档如何工作、编辑器支持哪些元素，以及应使用哪种文档格式。
- `tools` (`array`): AI 或开发者可以调用的工具定义。每个数组元素包含：
  - `name` (`string`): 工具名称。
  - `description` (`string`): 工具描述。
  - `inputSchema` (`object`): AI 生成的工具输入的 JSON schema。

示例：

```curl
curl --location 'BASE_URL/v4/ai/toolkit/fetch-tools' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT' \
  --data '{
    "editorContext": { /* 编辑器上下文数据 */ },
    "tools": {
      "tiptapRead": true,
      "tiptapEdit": {
        "meta": "简要解释此次编辑。"
      }
    },
    "format": "shorthandV2"
  }'
```

#### 错误响应

HTTP 错误会返回：

- `error` (`object`): 一个包含以下属性的对象：
  - `message` (`string`): 人类可读的错误消息。
  - `status` (`number`): HTTP 状态码。
  - `code` (`string`): 稳定的错误代码。
  - `data` (`object`, optional): 已清理的结构化上下文。

此端点可能返回：

- `401` with `access_control_auth_required` or `missing_token`: 请求未包含 Tiptap Access Control JWT。
- `401` with an access-control code such as `token_expired` or `signature_invalid`: JWT 未通过 Access Control 的验证。
- `403` with `feature_not_available`: 环境未启用服务器端 AI Toolkit。
- `403` with `insufficient_permissions`: JWT 未授予 `AI:Toolkit` 权限。
- `403` with `origin_not_allowed`: 请求的 `Origin` 不被该环境允许。
- `422` with `validation_failed`: 请求体与端点 schema 不匹配。响应包含 `error.issues`，其中列出验证问题。
- `422` with `tool_config_validation_failed`: 请求体中提供的工具配置无效。响应包含 `error.data.issues`，其中列出验证问题。
- `429` with `rate_limited`: Access Control 对身份验证请求进行了速率限制。
- `429`: 服务器端速率限制器阻止了请求。此响应使用不同的顶层结构：
  - `error` (`string`): 速率限制错误消息。
  - `retryAfter` (`number`, optional): 重试前需要等待的秒数。
  - `limit` (`number`, optional): 当前时间窗口内的请求限制。
  - `window` (`number`, optional): 速率限制窗口的秒数。
- `500` with `internal_server_error`: 发生了意外的服务器错误。
- `500` with `missing_cloud_api_token`: 云服务缺少内部身份验证配置。
- `503` with `service_unavailable`: Access Control 暂时不可用。

### 执行工具

```txt
POST /v4/ai/toolkit/execute-tool
```

执行一个工具。在 AI 模型生成工具调用后使用此端点。

请求体：

- `editorContext` (`object`，必需)：`getEditorContext` 返回的编辑器上下文。
- `document` (`object`，必需)：要对其执行工具的文档。API 需要从 Tiptap Cloud 文档读取并写入时，使用
  `{ "type": "cloud", "id": "your-document-id" }`。当你想在请求体中提供
  Tiptap JSON 文档时，使用 `{ "type": "inline", "content": { /* Tiptap JSON 文档 */ } }`。
- `user` (`string`，可选)：版本历史中编辑的作者。它还会设置 AI 生成的评论、线程和修订记录建议所关联的用户；
  如需设置修订记录建议的作者，请使用 `reviewOptions.trackedChangesOptions.userId`。
- `field` (`string`，可选，默认：`"default"`)：要在云文档中定位的协作字段。文档存储多个可编辑字段时使用此项，例如标题和正文。
- `tool` (`object`，必需)：要执行的工具调用。
  - `name` (`string`，必需)：工具名称，例如 `"tiptapRead"`。
  - `input` (`object`，必需)：AI 生成的工具输入。这是一个与该工具的 schema 和工具定义相匹配的对象。每个工具的 schema 和工具定义可从
    `/v4/ai/toolkit/fetch-tools` 端点获取。
  - `config` (`unknown`，可选)：由开发者提供的工具特定配置。
- `format` (`'json' | 'shorthand' | 'shorthandV2'`，可选，默认：`'json'`)：工具输入和输出的文档格式。参见 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。
- `reviewOptions` ([`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认：`{ mode: 'disabled' }`)：控制编辑是直接应用还是作为可审阅更改应用。

响应：

- `tool` (`object`)：已执行的工具及其输出。
  - `name` (`string`)：工具名称。
  - `output` (`object`)：提供给 AI 的工具输出。
- `docChanged` (`boolean`)：文档是否发生了变化。
- `before` (`JSONContent`)：工具执行前的 Tiptap JSON 文档。
- `document` (`JSONContent | null`)：工具执行后的 Tiptap JSON 文档；如果文档未更改则为 `null`。变化可能包括文档内容以及节点 `_hash` 属性的修改；这些属性用作唯一标识符，使 AI 能够选择文档节点。

示例：

```curl
curl --location 'BASE_URL/v4/ai/toolkit/execute-tool' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT' \
  --data '{
    "editorContext": { /* 编辑器上下文数据 */ },
    "document": {
      "type": "cloud",
      "id": "your-document-id"
    },
    "user": "ai-assistant",
    "tool": {
      "name": "tiptapRead",
      "input": {
        "from": 0
      }
    },
    "format": "shorthandV2"
  }'
```

#### Error responses

HTTP errors return:

- `error` (`object`): An object with these properties:
  - `message` (`string`): Human-readable error message.
  - `status` (`number`): HTTP status code.
  - `code` (`string`): Stable error code.
  - `data` (`object`, optional): Sanitized structured context. Document and thread upstream
    failures include fields such as `operation`, `upstreamStatus`, `upstreamUrl`, and
    `upstreamMethod`.

This endpoint can return:

- `400` with `missing_document_credentials`: The request uses a cloud document, but the JWT does not
  include document server credentials.
- `400` with `missing_document_options`: `getThreads` or `editThreads` was executed against an
  inline document. These tools require a cloud document.
- `400` with a thread-store code such as `thread_not_found` or `comment_not_found`: A thread or
  comment operation referenced data that does not exist.
- `401` with `access_control_auth_required` or `missing_token`: The request did not include a
  Tiptap Access Control JWT.
- `401` with an access-control code such as `token_expired` or `signature_invalid`: The JWT was
  rejected by Access Control.
- `403` with `feature_not_available`: Server AI Toolkit is not enabled for the environment.
- `403` with `insufficient_permissions`: The JWT does not grant `AI:Toolkit`, or it does not grant
  access to the requested cloud document.
- `403` with `origin_not_allowed`: The request `Origin` is not allowed for the environment.
- `403` with `unsupported_tool_format`: The selected tool does not support the requested `format`.
- `403` with `tracked_changes_unsupported_schema`: `reviewOptions.mode` is `trackedChanges`, but
  the editor schema does not support tracked changes.
- `403` with `thread_schema_not_supported`: The editor schema does not support comments or threads.
- `403` 和 `board_schema_not_supported`：[白板工具](#board-tools) 获得的文档或编辑器模式不是可以使用的白板。
- `409` with `concurrent_edit_conflict`: The cloud document changed while the tool was executing.
  Retry the request with the latest document state.
- `422` with `validation_failed`: The request body does not match the endpoint schema. The response
  includes `error.issues`, a list of validation issues.
- `429` with `rate_limited`: Access Control rate-limited authentication.
- `429`: The server-side rate limiter blocked the request. This response uses a different top-level
  shape:
  - `error` (`string`): Rate limit error message.
  - `retryAfter` (`number`, optional): Seconds to wait before retrying.
  - `limit` (`number`, optional): Request limit for the current window.
  - `window` (`number`, optional): Rate-limit window in seconds.
- `500` with `document_save_failed`: The server could not save the cloud document after loading it,
  or the save flow was called before a document was loaded.
- `500` with `diff_worker_failed` or `diff_worker_invalid_result`: The internal diff worker failed
  while preparing reviewable changes.
- `500` with `internal_server_error` or `unknown_error`: An unexpected server error occurred.
- `500` with `missing_cloud_api_token`: The cloud service is missing internal authentication
  configuration.
- `502` with `document_load_failed` or `document_save_failed`: Loading or saving the cloud document
  failed upstream. Check `error.data.upstreamStatus` for the upstream HTTP status.
- `502` with a thread or comment code such as `thread_list_failed`, `thread_create_failed`,
  `thread_update_failed`, `thread_delete_failed`, `thread_resolve_failed`,
  `thread_unresolve_failed`, `comment_create_failed`, `comment_update_failed`, or
  `comment_delete_failed`: 评论 API 操作在上游失败。
- `503` with `diff_worker_queue_timeout`: diff worker 队列已饱和或超时。
- `503` with `service_unavailable`: 访问控制暂时不可用。

### 流式执行工具

```txt
POST /v4/ai/toolkit/stream-tool
```

以流式方式执行工具。`tiptapEdit` 可以逐步应用编辑，以实现打字效果。其他工具会在接收到完整输入后
运行，并返回一个最终事件，就像 `execute-tool` 一样。

请求分批发送。第一部分包含：

- `editorContext` (`object`，必需)：由 `getEditorContext` 返回的编辑器上下文。
- `document` (`object`，必需)：要将编辑流式写入的云文档：
  `{ "type": "cloud", "id": "your-document-id" }`。内联文档不支持
  流式传输。
- `user` (`string`，可选)：版本历史、评论和线程中编辑的作者（例如与 `editThreads` 一起使用）。它不会设置修订记录建议的作者；如需设置修订记录作者，请使用 `reviewOptions.trackedChangesOptions.userId`。
- `field` (`string`，可选，默认：`"default"`)：要在云文档中定位的协作字段。流式传输仅支持 `default` 字段；使用任何其他值都会被拒绝。
- `tool` (`object`，必需)：要执行的工具调用，不包含 `tool.input`。
  - `name` (`string`，必需)：工具名称，例如 `"tiptapEdit"`。
  - `config` (`unknown`，可选)：开发者提供的工具特定配置。
- `format` (`'json' | 'shorthand' | 'shorthandV2'`，可选，默认：`'json'`)：工具输入和输出的文档格式。参见 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。
- `reviewOptions` ([`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认：`{ mode: 'disabled' }`)：控制编辑是直接应用还是作为可审阅更改。
- `delayMs` (`number`，可选，默认：`5`)：`tiptapEdit` 增量输出中每个字符的延迟，单位为毫秒。必须介于
  `0` 和 `1000` 之间。使用 `0` 可尽可能快地应用编辑。

然后发送：

- 后续部分：`tool.input` 的值，在 AI 生成时以流式方式发送。

响应：

- `tiptapEdit`：在编辑被应用时返回增量事件，随后返回一个包含
  更新后 `document` 的最终事件。
- 其他工具：返回一个最终事件，结果结构与 `execute-tool` 相同。

#### 错误响应

在流式传输开始之前，HTTP 错误使用与 `execute-tool` 相同的 JSON 结构：

- `error` (`object`): 一个包含以下属性的对象：
  - `message` (`string`): 人类可读的错误消息。
  - `status` (`number`): HTTP 状态码。
  - `code` (`string`): 稳定的错误代码。
  - `data` (`object`, optional): 已清理的结构化上下文。

在流式传输开始之后，错误会以 NDJSON 事件形式发送：

- `version` (`number`): 流协议版本。
- `type` (`'error'`): 事件类型。
- `code` (`string`): 稳定的错误代码。
- `status` (`number`): 类 HTTP 状态码。
- `message` (`string`): 人类可读的错误消息。

此端点可能返回或发出：

- `400` with `invalid_request`: 请求没有正文。
- `400` with `missing_document_credentials`: JWT 不包含文档服务器凭据。
- `400` with `invalid_stream_message`: 流消息不是有效的 JSON，未通过 schema 验证，
  使用了不支持的协议版本，或者流在 NDJSON 行未终止时结束。
- `400` with `duplicate_start`: 发送了多个 `start` 消息。
- `400` with `delta_before_start`: `delta` 消息在 `start` 之前到达。
- `400` with `end_before_start`: `end` 消息在 `start` 之前到达。
- `400` with `incomplete_stream`: 请求在 `end` 消息到达之前结束。
- `400` with a thread-store code such as `thread_not_found` or `comment_not_found`: 缓冲的
  线程或评论操作引用了不存在的数据。
- `401` with `access_control_auth_required` or `missing_token`: 请求未包含
  Tiptap Access Control JWT。
- `401` with an access-control code such as `token_expired` or `signature_invalid`: JWT 被
  Access Control 拒绝。
- `403` with `feature_not_available`: 当前环境未启用 Server AI Toolkit。
- `403` with `insufficient_permissions`: JWT 未授予 `AI:Toolkit`。
- `403` with `origin_not_allowed`: 请求的 `Origin` 不被当前环境允许。
- `403` with `tracked_changes_unsupported_schema`: `reviewOptions.mode` 为 `trackedChanges`，但
  编辑器 schema 不支持跟踪更改。
- `403` with `thread_schema_not_supported`: 编辑器 schema 不支持评论或线程。
- `413` with `ndjson_line_too_long`: 单个 NDJSON 行超过了最大大小。
- `429` with `stream_rate_limit_exceeded`: 同一客户端打开的并发流过多。
- `429` with `rate_limited`: Access Control 认证被限流。
- `429`: 服务器端限流器在流式传输开始前阻止了请求。此响应
  使用不同的顶层结构：
  - `error` (`string`): 限流错误消息。
  - `retryAfter` (`number`, optional): 重试前等待的秒数。
  - `limit` (`number`, optional): 当前窗口的请求上限。
  - `window` (`number`, optional): 限流窗口，单位为秒。
- `500` with `diff_worker_failed`, `diff_worker_invalid_result`, `stream_internal_error`, or
  `unknown_error`: 流处理期间发生了意外的服务器错误。
- `500` with `missing_cloud_api_token`: 云服务缺少内部身份验证
  配置。
- `502` with document, thread, or comment upstream failure codes such as `document_load_failed`,
  `document_save_failed`, `thread_list_failed`, or `comment_create_failed`: 云文档或
  评论 API 操作在上游失败。
- `503` with `diff_worker_queue_timeout`: diff worker 队列已饱和或超时。
- `503` with `service_unavailable`: Access Control 暂时不可用。
- `504` with `stream_request_timeout`: 流超过了服务器请求超时时间。

## 可用工具

这些工具可供 AI 代理使用。代理决定调用哪个工具。

所有工具默认都处于禁用状态。我们建议先使用 `tiptapRead` 和 `tiptapEdit`，然后
根据需要启用其他工具。

你也可以直接从应用程序代码中调用这些工具，以构建自定义工作流。

### `tiptapRead`

分块读取文档，以避免上下文窗口溢出。

工具输入（`tool.input`）：

- `from` (`number`，必需)：要读取的第一个顶层节点的从零开始的索引。必须是
  非负整数。

工具配置（`tool.config`）：

- `chunkSize`（`number`，可选）：每次工具调用中读取的最大字符数。默认值：`32000`

工具输出（`tool.output`）：

成功响应：

- `success`（`true`）：表示读取请求成功。
- `totalNodeCount`（`number`）：文档中顶层节点的总数。
- `nodeRange`（`[number, number]`）：读取的顶层节点范围。
- `content`（`JSONContent[] | string`）：所返回范围内的文档内容。当 `format` 为
  `json` 时，这是一个 Tiptap JSON 片段。当 `format` 为 `shorthand` 或
  `shorthandV2` 时，这是一个 Tiptap Shorthand 字符串。

错误响应：

- `success`（`false`）：表示读取请求失败。
- `error`（`string`）：错误信息。
- `totalNodeCount?`（`number`）：顶层节点总数。

### `tiptapEdit`

编辑文档内容。

工具输入（`tool.input`）：

- `operations`（`array`，必需）：一个或多个编辑操作，按顺序应用。
  - `type`（`'replace' | 'insertBefore' | 'insertAfter'`，必需）：要执行的编辑类型。
  - `target`（`string`，必需）：选择要应用操作的文档节点，或整个文档。它是所选节点的 `_hash` 属性值，或用于选择整个文档的 `"doc"`。

## 主板工具

<Callout title="Alpha 功能" variant="hint">
  主板工具目前处于 alpha 版本
</Callout>

这些工具读取和更改 [whiteboard](/editor/whiteboard/getting-started/overview).在董事会文档上使用董事会编辑器的编辑器上下文执行它们。请参阅[与 Whiteboard](/ai/ai-toolkit/agents/whiteboard) 一起使用进行设置。

电路板工具采用纯文本，而不是文档内容，因此它们在每个 `format` 中的工作方式相同。它们无法通过 `stream-tool` 获得。

无法运行的板工具没有任何改变。当模型可以修复调用时，例如与板上不匹配的架构或 id 的输入，该工具会使用 HTTP 状态 `200` 进行应答，并在其工具输出中使用 `success: false` 和 `error`。

当请求本身无法工作时，`execute-tool` 会像其他工具一样失败：

- `403` 和 `board_schema_not_supported`：文档或编辑器上下文不是该工具可以处理的白板，就像没有 `createDocFrame` 文档框架的白板。
- `403` 和 `tracked_changes_unsupported_schema`：`reviewOptions.mode` 是 `'trackedChanges'`，用于更改电路板的工具，但编辑器上下文没有跟踪更改。 `readBoard` 不检查此项。

### 板工具配置

`readBoard`、`createShapes`、`createDiagram` 和 `createDocFrame` 采用此工具配置 (`tool.config`)：

- `selectedIds`（`string[]`，可选）：形状的 ID用户选择的内容，按照选择的顺序。
- `viewport`（`{ x: number, y: number, width: number, height: number }`，可选）：用户看到的板部分，以板为单位。 `width` 和 `height` 必须高于 `0`。

每个缺失、`null` 或无效的字段都会自行回退：不进行选择，或不进行视口。

### 电路板放置

`createShapes`、`createDiagram` 和 `createDocFrame` 在其输入 (`tool.input`) 中采用这些字段，因此 AI 可以为新内容命名位置：

- `near`（`string[]`，可选）：最多新内容所属形状的 100 个 id，例如摘要所涉及的图表。默认为选定的形状。
- `side`（`'right' | 'below' | 'left' | 'above'`，可选）：新内容的这些形状的侧面。当空闲点较近时，默认为 `'right'` 或 `'below'`。

新形状位于棋盘上 `near` 中的形状旁边，或者位于所选形状旁边。如果没有这样的形状，它们将位于视口的中间，或者位于板上所有形状的右侧，或者位于空板的原点。当其他形状挡路时，它们会移动到最近的自由点。

### 电路板建议

使用 `reviewOptions.mode: 'trackedChanges'`，电路板工具将其更改写入为 [跟踪更改](/tracked-changes/getting-started/overview):

- ] 的建议。 一次调用添加或删除的形状共享一个建议，因此 `acceptSuggestion` 或 `rejectSuggestion` 会审核所有这些建议。
- 每个更改的形状和每个新文本都会得到自己的建议。稍后等待同一用户审核的形状更改将纳入该建议。
- 这些工具会单独留下等待其他用户审阅的形状，或等待审阅将其删除的形状，并且不会删除等待审阅更改的形状。他们在 `skipped` 或 `skippedArrows` 中说明了原因。

`suggestionIds` (`string[]`) 列出呼叫发出或继续进行的建议。调用继续进行的建议也保留了先前的更改，并且对先前建议添加的形状的更改是该添加的一部分，因此未列出。当您查看这些 ID 时，其他建议保持不变。如果没有审查，`suggestionIds` 是空的，并且工具会保留每个等待审查的形状。

工具配置 (`tool.config`):

[板工具配置](#board-tool-config)。

工具输出 (`tool.output`)：

成功响应：

- `success` (`true`)：表示已绘制图表。
- `createdIds` (`string[]`)：所有新形状的 ID：标题、形状、箭头及其标签。
- `nodeIds` (`Record<string, string>`)：每个新形状的 ID（按其键）。
- `skippedArrows` (`array`)：省略的箭头，每个箭头都有 `from`、`to` 和 `reason`。带有未知键的箭头（从形状到自身）或较早出现的箭头将被忽略。
- `suggestionIds` (`string[]`)：请参阅[董事会建议](#board-suggestions)。

错误响应：

- `success` (`false`)：表示未绘制图表。
- `error` (`string`)：错误消息。

### `updateShapes`

更改文本、颜色或形状种类。形状保持其位置和大小。

刀具输入（`tool.input`）：

- `shapes`（`array`，必填）：1 至 40 个形状，每个形状一次，仅更改内容。
  - `id`（`string`，必需）：形状的 ID。
  - `text`（`string`，可选）：新文本，最多 500 个字符，行数与 `createShapes` 相同。它替换形状的文本，但不设置其格式。 `readBoard` 为形状提供的文本没有变化。只有便利贴、几何形状和自由文本才有文本。
  - `color`（`string`，可选）：新颜色，`createShapes`的颜色之一。
  - `kind`（`'rectangle' | 'ellipse' | 'diamond' | 'triangle'`，可选）：新型几何形状。

工具配置 (`tool.config`)：

`null`

工具输出 (`tool.output`)：

成功响应：

- `success` (`true`)：表示至少有一个形状发生了变化。
- `updatedIds` (`string[]`)：已更改形状的 ID。
- `skipped` (`array`)：保持原样的形状，每个形状都有 `id` 和 `reason`，就像等待其他用户审阅的形状，或者没有文本但获得 `text` 的形状。
- `suggestionIds` (`string[]`)：请参阅[董事会建议](#board-suggestions)。

错误响应：

- `success` (`false`)：表示形状没有改变。该错误列出了原因。
- `error` (`string`)：错误消息。

### `deleteShapes`

删除形状，包括箭头。连接已删除形状的箭头保留自由端。

刀具输入 (`tool.input`)：

- `ids`（`string[]`，必需）：1 至 100 个形状 ID。

工具配置 (`tool.config`)：

`null`

工具输出 (`tool.output`)：

成功响应：

- `success` (`true`)：表示形状已删除。经过审核，他们会保留 `delete` 建议，直到用户接受为止。
- `deletedIds` (`string[]`)：已删除形状的 ID。
- `skipped` (`array`)：留在棋盘上的形状，每个形状都有 `id` 和 `reason`，就像不是棋盘上形状的 id，或者等待审核的形状。
- `suggestionIds` (`string[]`)：请参阅[董事会建议](#board-suggestions)。

错误响应：

- `success` (`false`)：表示未删除任何形状。该错误列出了原因。
- `error` (`string`)：错误消息。

### `connectShapes`

在板上的形状之间绘制箭头，每个形状旁边都有一个可选标签。

刀具输入 (`tool.input`)：

- `arrows`（`array`，必需）：1 至 40 个箭头。
  - `from`（`string`，必需）：箭头开始处的形状的 ID。
  - `to`（`string`，必需）：箭头指向的形状的 ID。
  - `label`（`string`，可选）：箭头旁边的标签，最多 24 个字符。

工具配置 (`tool.config`)：

`null`

工具输出 (`tool.output`)：

成功响应：

- `success` (`true`)：表示至少绘制了一个箭头。
- `createdIds` (`string[]`)：新箭头和标签的 ID。
- `skippedArrows` (`array`)：被遗漏的箭头，每个箭头都有 `from`、`to` 和 `reason`：未知形状、从形状到自身的箭头、等待删除的形状或棋盘上已有的箭头。
- `suggestionIds` (`string[]`)：请参阅[董事会建议](#board-suggestions)。

错误响应：

- `success` (`false`)：表示未绘制箭头。该错误列出了原因。
- `error` (`string`)：错误消息。

### `createDocFrame`

在所有形状前面添加带有新的空文档的文档框架。用`tiptapEdit`写文档，在其`docId`的Tiptap Cloud文档上。参见[编写文档框架](/ai/ai-toolkit/agents/whiteboard#write-the-documents-of-doc-frames)的文档。

Tool input (`tool.input`):

- `lines`（`number`，可选）：关于文档将有多少行，作为从 1 到 400 的整数。框架为它们保留了空间。默认值：`12`
- `near` 和 `side`（可选）：帧所在的位置。请参阅[董事会布局](#board-placement)。

Tool config (`tool.config`):

[板工具配置](#board-tool-config)。

Tool output (`tool.output`):

Success response:

- `success` (`true`)：表示帧已添加。
- `frameId` (`string`)：新帧的 ID。
- `docId` (`string`)：框架文档的 ID。
- `suggestionIds` (`string[]`)：请参阅[董事会建议](#board-suggestions)。

Error response:

- `success` (`false`)：表示没有添加帧。
- `error` (`string`): Error message.
